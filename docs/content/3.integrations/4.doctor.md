The scanner reads build output, so markup that only appears at runtime can be missed: `v-html`, CMS or markdown content, `<component :is>`, fully dynamic attributes. The doctor loads your pages in a headless browser and compares the **live DOM** with what each page's stylesheet shipped.

```bash
blue-css doctor dist                              # static build: every *.html is a starting page
blue-css doctor http://localhost:3000 --crawl     # running server: follow same-origin links
```

```
Missing modules (2): elements on these pages have no Blue styles
  ✗ dialog (+ motion)  on /cms.html
      tag:dialog ×1
        dialog#promo
  ✗ tabs  on /cms.html
      attr:role=tablist ×1
        main#content > div[role=tablist]

This markup only exists at runtime (v-html, CMS/markdown content, dynamic tags),
so the build-time scan could not see it. Ship the modules anyway with:
  safelist: ['dialog', 'tabs']
```

## How it knows

Every Blue stylesheet declares what it contains in a `--blue-modules` custom property on `:root`. The doctor reads it from the live page, so it works whichever integration delivered the CSS.

## Options

| Option | |
|---|---|
| `--crawl` | Follow same-origin links |
| `--max-pages <n>` | Stop after `n` pages (default 50) |
| `--wait <ms>` | Extra wait after load, for client-rendered content |
| `--root <dir>` | Where absolute paths resolve when given HTML files |
| `--json` | Machine-readable report |

- It exits with code 1 when anything is missing, so it can gate CI.
- It also lists modules shipped but unused on every inspected page — a hint the scan over-included.
- Opted-out subtrees (`data-blue="off"`) and shadcn components (`[data-slot]`) are ignored.
- Content that appears only after a click (menus, portals) is not in the DOM at load time; safelist it.

::note
The doctor needs Playwright: `pnpm add -D playwright && pnpm exec playwright install chromium`.
::
