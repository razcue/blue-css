```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@blue-css/nuxt'],
  blue: {
    safelist: [],   // module ids or tokens for content rendered at runtime
    content: [],    // extra globs to scan, e.g. 'content/**/*.md'
    presets: [],    // e.g. '@blue-css/preset-reka'
  },
})
```

## What it does

- **`nuxi dev`** adds the complete stylesheet. Nothing is scanned, so nothing can be missing while you iterate.
- **`nuxi build` / `nuxi generate`** builds the tree-shaken stylesheet once Vite has produced both bundles, from:
  - every client chunk — your code and what libraries render;
  - your app's own modules in the server build, so **server components and islands** are covered (server-side `node_modules` are skipped: the unminified Vue runtime is full of strings like "v-model on `<input>`");
  - any extra `content` globs.
- Writes `_nuxt/blue.<hash>.css`, which Nitro serves with immutable caching, and links it from every **SSR, prerendered and SPA** page through a Nitro `render:html` hook. Runtime `baseURL` and `cdnURL` are honoured.

## Options

| Option | Default | |
|---|---|---|
| `safelist` | `[]` | Module ids (`'dialog'`) or tokens (`'attr:role=tab'`) that always ship |
| `content` | `[]` | Extra globs, relative to the project root |
| `presets` | `[]` | Preset manifests or package names |
| `reset` | `true` | Ship Blue's reset; set `false` next to Tailwind's preflight |
| `minify` | `true` | Minify the output |
| `report` | `true` | Log a one-line size summary after the build |

::tip
Content from `@nuxt/content`, a CMS or `v-html` is invisible to a build-time scan. Run [`blue-css doctor`](/integrations/doctor) on the built site and add what it reports to `safelist`.
::
