Pick the integration for your stack. Each serves the **full** stylesheet in development and a **tree-shaken** one in production builds.

## Nuxt

::code-group
```bash [pnpm]
pnpm add -D @blue-css/nuxt
```
```bash [npm]
npm install -D @blue-css/nuxt
```
::

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@blue-css/nuxt'],
})
```

`nuxi build` and `nuxi generate` scan every client chunk plus your app's server modules (server components and islands included), write `_nuxt/blue.<hash>.css` and link it from every SSR, prerendered and SPA page. See [Nuxt](/integrations/nuxt) for options.

## Vite

::code-group
```bash [pnpm]
pnpm add -D @blue-css/vite
```
```bash [npm]
npm install -D @blue-css/vite
```
::

```js [vite.config.js]
import blue from '@blue-css/vite'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [blue()],
})
```

The plugin links the stylesheet from `index.html`. See [Vite](/integrations/vite).

## Any other build

Run the CLI after your framework's build, against its output:

```bash
pnpm add -D @blue-css/cli
astro build && blue-css build dist -o dist/blue.css --report
```

Then link `blue.css` from your pages. See [CLI](/integrations/cli).

## No build at all

Link the complete stylesheet. Everything works; nothing is shaken.

```html
<link rel="stylesheet" href="https://unpkg.com/@blue-css/core/dist/blue.min.css">
```

::note
Using Tailwind CSS or shadcn too? Read [Tailwind and shadcn](/getting-started/tailwind-and-shadcn) — it is one line of CSS.
::
